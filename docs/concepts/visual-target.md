# 视觉目标卡 · 病理补充报告生成系统

> 本项目**没有图形界面**（交付形态是常驻守护进程 + 运维 CLI），因此视觉目标不落在网页上，
> 而落在**三个真实会被看到的地方**：运维终端会话、守护进程运行日志、导出的报告页。
> 本环境不具备图像生成能力，故只写结构化视觉目标卡，**不伪造概念图**；
> 真实运行截图由收尾任务采集到 `docs/screenshots/`。

---

## 一、三个状态

### 状态 1 · 起始态（部署完成，尚未收到结果）

画面是**空转的终端**。光标停在提示符上，屏幕上只有一行启动横幅与一行心跳：

```
patho-supplement 0.1.0 · 常驻运行中
  监听结果目录 /data/patho/inbox · 状态库 /data/patho/state.db · 下一轮扫描 2s 后
[启动恢复] 挂起项 0 条 · 回写队列 0 条 · 结果目录待处理 0 个文件
```

- **画面类型**：终端会话（守护进程前台运行）
- **此刻画面上有什么**：启动横幅一行、监听路径与状态库路径、下一轮扫描倒计时，以及
  **一行启动恢复**（重启之后手上还剩多少活：挂起项 / 回写队列 / 目录里没归档的报文）；
  **没有**结果计数表（此时还没有任何结果可数，硬画一个空表格是假的）
- **不该出现**：大段日志、进度条、彩色告警

### 状态 2 · 首个可用瞬间（一批结果到达，出一份草稿）

这是**最关键的一屏**：结果刚被处理完，运维既要看「处理了多少」，又要立刻看到
「有没有对不上的」。画面分两段：

```
[06:14:22] 事件 文件 ORU_20261028_001.hl7 · 病理号 SP-2026-0031 · 结果 6 条
[06:14:22] 对齐 命中 5 条（L1 蜡块号精确 4 / L2 部位精确 1）· 挂起 1 条
[06:14:23] 回写 草稿 v1 已写入病理系统草稿区 · 接受版本 12
[06:14:23] 通知 已发当班医师（排班命中）· 草稿待签发
[06:14:23] 本轮 处理 6 · 对齐 5 · 挂起 1 · 回写成功 1 · 失败 0 · 耗时 1.2s
```

- **画面类型**：服务运行日志（守护进程 stdout，结构化行）
- **此刻画面上有什么**：每行一个事件（事件、对象、数量），最后一行是**本轮摘要**（处理 / 对齐 /
  挂起 / 回写成功 / 回写失败 / 耗时六项）
- **这一屏必须能回答的问题**：结果收到了没有？对上了几条？没对上几条？草稿写进去了没有？
  —— 五个问题全部由最后一行摘要给出，不需要翻日志

### 状态 3 · 成形态（技术员处理完挂起项，闭环完成）

技术员拿到的是**一份可带走的清单**，以及补齐后系统给出的回执：

```
待人工处理清单 · 病理号 SP-2026-0031 · 共 1 条
--------------------------------------------------------------------------------
[1] 项目码 IHC-ER          缺失字段：蜡块号            尝试次数：1
    回报部位描述：子宫体内膜           回报时间：2026-10-28 05:41
    候选部位： #2 子宫体（B2） / #3 宫颈（B3）
    建议动作：核对蜡块登记后补齐「蜡块号」再续跑
--------------------------------------------------------------------------------

补齐后：
[06:31:07] 挂起 #1 已人工补齐（蜡块号=B3）· 续跑命中 L1 蜡块号精确 · 并入草稿 v2
[06:31:07] 回写 草稿 v2 已写入病理系统草稿区 · 接受版本 13 · 草稿 v1 保留可回查
```

- **画面类型**：导出的报告页（纯文本清单，终端里直接看，也可导出成文件带走）
- **此刻画面上有什么**：编号条目、缺哪个字段、回报了什么、**候选是谁**、补齐后系统的接住回执
- **不该出现**：只有「对不上」三个字却不写缺哪个字段 —— 技术员无法据此判断该查蜡块登记还是查回报口径

## 二、视觉语言

| 维度 | 取值 | 说明 |
|---|---|---|
| 背景 | `#0F1115`（终端深色）/ 导出清单用 `#FFFFFF` | 守护日志走深色终端；清单要能打印，故导出用白底 |
| 正文 | `#D7DBE0` | 日志正文 |
| 主信息 | `#4C9AFF` | 事件名（事件 / 对齐 / 回写 / 通知） |
| 成功 | `#3FB950` | 命中、已回写 |
| 警告 | `#D29922` | 挂起、降级、缺字段 |
| 失败 | `#F85149` | 拒收、回写失败 |
| 辅助信息 | `#6E7681` | 时间戳、耗时、路径 |
| 字体族 | 终端：SF Mono / Menlo / Cascadia Mono；正文说明：PingFang SC / Microsoft YaHei | 数字与项目码一律等宽，便于纵向比对 |
| 信息层级 | ①事件名（最亮）②对象标识（次亮）③数量与耗时（辅助灰） | 一行内从左到右也是由亮到暗 |
| 对齐方式 | 「事件」列固定 8 字符宽并左对齐，「数量」列右对齐 | 日志逐行扫读时列不跳动 |
| 留白密度 | 行间一行空白；清单每条之间空一行 | 挂起条目信息量大，挤在一起会读错条目归属 |

## 三、必须可达的约束

只列**用当前依赖真能做出来**的元素。凡是下面做不到的，一律不出现在目标画面里。

1. **纯文本终端输出**：运行时零第三方依赖，终端着色用 ANSI 转义序列手写（16 色 + 亮色），
   不引 rich/textual 之类渲染库。
2. **结构化行日志**：每行 `时间 级别 事件 对象 数量 耗时`，字段用固定宽度分隔，
   一行一事件——不引日志框架，自带 `logging_setup.py`。
3. **导出的报告页**：Markdown / 纯文本清单，由 `pending export` 生成 CSV + 文本两种文件，
   文本版带表头与统计摘要，能直接打印带去查登记。
4. **无网页、无图形控件**：本轮不引入 Web 框架与前端，因此**不出现**按钮、表单、图表、
   仪表盘、进度环等任何图形元素。
5. **无模型输出画面**：本产品 `ai_role = none`，屏幕上不会出现任何「模型建议」「生成中」
   字样；所有文字来自报文与规则判定。
6. **不虚构数字**：画面上的条数、耗时、版本号全部来自真实运行，
   概念图与实测必然有差距，由收尾截图如实呈现。
